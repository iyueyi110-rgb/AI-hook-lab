# 产品决策简报

> 版本：2026-08-06。本文区分已验证事实、方法实现和待验证假设；当前没有可验证的真实用户任务结果。

## 目标用户与核心任务

第一目标用户是假设中近一个月持续发布内容、已经拥有真实选题，但在开头表达上需要快速比较方案的中文内容创作者。第二目标用户是需要复盘 Prompt、人工反馈和 Bad Case 的内容运营人员。

核心任务不是“让模型写一句看起来吸引人的话”，而是帮助创作者在同一主题下完成候选比较、选择、必要改写和使用方式确认，并让后续版本决策能够追溯到人工证据。

当前仓库能够证明该工作流和治理方法已经实现，不能证明目标用户一定存在上述痛点，也不能证明生成结果已经被真实采用或发布。

## 当前关键假设

| 假设 | 当前证据 | 验证方式 |
| --- | --- | --- |
| 同一主题的多候选比较比单条生成更有助于做决定 | 产品流程和固定评测方法已实现，没有真实任务对照 | 记录真实任务的完成、选择、改写和放弃原因 |
| 10 条候选能覆盖足够差异且不会造成过高比较负担 | 生成契约和界面支持 10 条，没有用户可用性证据 | 比较 5 条与 10 条的完成时间、选择率和主观负担 |
| 结构化平台、内容类型和受众约束能减少泛化输出 | Prompt 与字段规则已实现，没有正式人工评测结果 | 完成固定案例双人盲评并分析平台错配 Bad Case |
| 人工使用方式比模型自评分更接近产品价值 | 指标和反馈字段已实现，没有真实用户分子分母 | 执行至少 30 个有效真实任务并报告反馈覆盖率 |

## 已作出的产品取舍

1. **经典生成保持默认，Agent 按需介入。** 主题明确的用户先走短路径；只有需要补全简报或继续打磨时才打开 Agent，避免把技术模式选择变成首屏负担。
2. **保留 10 条候选，但把数量视为待验证参数。** 当前不因缺少用户证据擅自改成 3 条或 5 条，未来通过任务时间和选择结果决定。
3. **模型评分只解释差异。** 收藏、最终选择、使用方式和人工盲评由人产生，模型分不得命名为点击率、采用率或传播效果。
4. **所有来源隔离。** `real_user`、`evaluation_set` 和 `simulation` 分开计算，Mock 或不完整评测永远不能形成升级结论。
5. **保留现有后台能力，但停止横向扩展。** 运营 Agent、评测和策略治理作为二级方法证据保留；真实用户验证完成前不新增功能模块。

## 被否决的方案

| 方案 | 否决原因 | 当前处理 |
| --- | --- | --- |
| 用模型自评分或 Mock 收藏证明产品效果 | 指标来源错误，无法代表用户行为 | 只用于排序、流程测试和解释 |
| 根据简历中的百分比反向补造原始数据 | 不可复核，会破坏作品集可信度 | 所有缺证数字保持 `not_verified` |
| 为通过门禁而新建 Git 历史 | 会丢失原提交和追踪关系 | 从远程主仓库恢复有效工作树 |
| 向普通用户展示 Key 和 `.env.local` 配置方法 | 把维护者问题转嫁给用户，并暴露内部实现 | 改为安全、可恢复的服务不可用提示 |
| 在真实验证前继续扩展新 Agent 或后台模块 | 增加维护成本，不能回答用户是否愿意采用 | 保留现有实现，P0 转向证据与主路径 |

## 当前 P0 与决策门槛

当前 P0 是完成安全交付和可执行研究准备，而不是宣布业务成功。真实创作者验证尚未执行，因此不能恢复用户人数、收藏率、选择率、发布率或离线提升值。

未来只有在以下条件同时满足后，才讨论 Prompt 或产品主路径升级：

1. 真实任务具备可关联 `taskId`、Prompt 版本、完成状态和来源。
2. 报告给出整数分子分母、排除规则、任务覆盖率和反馈响应率。
3. 完整固定案例评测、双人盲评和必要裁决完成。
4. Bad Case 与安全护栏没有新增高风险问题。
5. 产品负责人检查反例并作出人工批准。

详细证据状态见[公开证据索引](../evidence/README.md)，研究执行方式见[真实创作者验证计划](../product/real-user-validation-plan.md)。
