# 作品集验收与简历对齐记录

本记录用于把仓库可复核事实、待补证据和简历表述放在同一条验收链路中。它不新增测试数据，也不把方法实现改写成真实用户结果。

## 证据分级

| 级别 | 定义 | 当前内容 | 对外写法 |
| --- | --- | --- | --- |
| 已验证事实 | 仓库中存在可复核文件、代码、测试或可重复命令 | 20 个主题 × 3 个平台的 60 个固定案例；创作 Agent 与运营分析 Agent 的规则、测试和安全门禁 | 可以陈述实现与评测方法，同时说明不代表真实传播效果 |
| 方法已实现 | 流程、指标或决策规则已固化，但没有完整业务样本 | 人工盲评、第三人裁决、来源隔离、Bad Case 护栏与 Prompt 升级门槛 | 只能写“设计并实现方法”，不能写成已发生的提升或升级决定 |
| 未验证主张 | 缺少脱敏原始记录、整数分子分母、正式导出或可复算结果 | 简历中的受控测试人数、任务数、产出数、收藏比例、选择比例和离线提升值 | 从简历与公开结论中删除；补证后按实际计算结果恢复 |
| 人工待验收 | 自动检查通过，但真实设备或交互主路径未完成复核 | 在线 Demo 的手机流量、无痕浏览器与桌面交互 | 暂不作为公开入口 |

详细主张状态见 [简历主张审计](../evidence/claims-audit.md)，指标名称与分子分母见 [指标字典](../evidence/metrics-dictionary.md)。

## 简历待同步清单

以下数字在真实脱敏 CSV、计算脚本和口径报告齐备前，保持 `not_verified`：

- 目标创作者人数、受控任务次数与 Hook 产出数量。
- 收藏比例与测试内最终选择比例；不得把测试内选择写成真实发布采用。
- 离线可用率和平台适配率的提升值。
- 缺少逐条标签时的主要 Bad Case 分布结论。

恢复任何数字前，必须同时满足：

1. 原始记录已脱敏，且可以关联任务、Hook、Prompt 版本与 `dataOrigin`。
2. 报告明确分子、分母、排除条件、时间范围和样本量。
3. 仓库计算脚本能从原始记录复算结果，不从简历数字反推数据。
4. 由本人检查反例、Bad Case 和护栏，再决定是否同步简历。

## 本轮验收记录

| 验收项 | 命令或记录 | 结果字段 | 结论 |
| --- | --- | --- | --- |
| 中文文档门禁 | `npm run docs:check` | 通过时填写文件数；失败时记录文件与行号 | 纯英文说明性标题、正文和展示型待办不得进入公开文档 |
| 自动化测试 | `npm test` | 填写通过数、失败数 | 验证现有产品规则与新增文档检查规则 |
| Agent 离线验收 | `npm run eval:agent` | 填写通过数、失败数 | 只属于离线夹具测量 |
| 静态检查 | `npm run lint` | 填写退出码 | 不替代业务验收 |
| 生产构建 | `npm run build` | 填写退出码 | 只证明当前代码能够构建 |
| 密钥扫描 | `npm run security:scan` | 填写扫描文件数与命中数 | 不打印命中值 |
| 证据清单 | `npm run evidence:verify` | 填写已验证与暂缓数量 | 暂缓主张不得进入公开结论 |
| 补丁格式 | `git diff --check` | 填写退出码 | 禁止空白错误 |
| Demo 自动复核 | [Demo 验证记录](demo-verification.md) | 2026-07-27：HTTPS 自动请求 200、TLS 校验通过 | 不能替代三端人工验活 |

最终门禁的精确结果应写入 PR 验收记录，不在本文伪造或预填“通过”。
