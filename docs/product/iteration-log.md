# 迭代记录

## 2026-08-07

- 证据：真实用户验证此前只有研究计划和指标口径，缺少可直接执行的招募、同意、主持、任务级记录、退出和脱敏材料；面试材料只有演示顺序，没有逐字稿和失败兜底。
- 判断：在不接触外部用户、不部署和不虚构数据的边界内，当前最有价值的修改是把研究与求职交付从“方向正确”推进到“可执行、可复核”。
- 实施：新增真实创作者研究执行包、空白研究工作簿和产品经理面试交付包；工作簿分离参与者、任务、逐 Hook 反馈、指标汇总、数据质量和字段字典。
- 护栏：空白模板不形成研究结论；少于 30 个有效任务只报告观察和整数计数；发布采用只在单独授权回访后计算；三类数据来源继续隔离。
- 招聘判断：研究准备完成使作品集评分由 83 调整为 84，但真实用户与部署证据仍为空白，招聘结论保持“建议进入实习面试，不能仅凭本项目录用”。
- 下一步：由产品负责人审批实际招募、报酬、同意文本和保留期限后执行研究；本阶段不联系参与者、不提交 Git、不部署。

## 2026-08-06

- 证据：远程主仓库的 316 项既有测试、Lint、生产构建、密钥扫描和证据核验通过；本地无 Key 主路径暴露开发配置说明，Agent 补全表单兜底仍有英文，公开文档门禁被一段英文验收结论阻塞。
- 判断：当前最需要提升的不是继续扩展 Agent 或后台模块，而是让主路径错误可恢复、招聘阅读路径清楚，并保持未验证主张不进入公开结论。
- 否决：不新建 Git 历史掩盖损坏交付包；不向普通用户展示 `.env.local` 或 Key 配置；不补造真实用户、收藏率或提升值；不在完成验证前继续增加新功能模块。
- 实施：从远程 `main` 恢复有效工作树，统一中文和用户安全错误文案，补充契约测试，并整理产品决策、验证计划和验收记录。
- 下一步：在不虚构数据的前提下完成作品集证据链；未来获得明确授权后，再执行 5–8 名创作者、至少 30 个真实任务的验证。
- 阶段五验收：使用系统临时目录完成全量 Mock 状态流转和三类角色复核；修复评测初始化同源误判、完成态 A/B 计数错误及生成失败埋点契约不一致。
- 最终门禁：327 项自动化测试、Lint、生产构建、密钥扫描和证据核验通过；Mock 完成态仍被报告门禁阻止升级。
- 招聘判断：项目达到产品经理实习面试线，证据意识与产品治理是优势；真实用户验证、线上部署一致性和人工三端验活仍是明确缺口。
