# 看板免登录设计

## 目标

允许线上部署在明确开启配置时公开访问 `/admin/dashboard`，并让看板筛选和刷新使用的只读汇总接口正常工作。评测工作区、账号管理、运营分析 Agent、数据写入接口和其他管理能力继续沿用现有登录与角色校验。

## 方案

新增服务端环境开关 `PUBLIC_DASHBOARD_ENABLED`。仅当值严格等于 `true` 时，应用把数据看板视为公开只读页面；未配置、配置为其他值或移除变量时，现有管理员登录流程保持不变。

公共访问判断集中在独立的纯函数中，页面和 API 复用同一规则：

- `/admin/dashboard`：公开模式下跳过评测会话与管理员角色检查，直接读取汇总数据并渲染看板。
- `GET /api/dashboard/summary`：公开模式下跳过会话与角色检查，使筛选和刷新继续可用。
- `/admin/dashboard/agent`、`/evaluation` 及其 API：不使用该开关，继续要求登录和相应角色。
- `POST /api/dashboard/events`：保持现有写入校验和数据来源规则，不因公开看板改变。

公开模式下，看板不展示“运营分析 Agent”和“离线评测”等受保护入口，避免匿名访问者点击后进入登录页；登录模式下保持现有界面。

## 数据与安全边界

免登录意味着任何知道网址的人都能读取看板当前展示的聚合指标和最近事件。该变更不开放账号数据、评测运行详情或写操作，也不创建匿名管理员身份或伪造会话。

环境变量只在服务端读取，不发送到浏览器。开关默认关闭，恢复登录只需移除变量或设为非 `true` 后重新部署。

## 错误处理

数据库未配置或不可用时，继续返回现有的不可用页面或 `503` 响应。查询参数校验、数据库异常处理和看板客户端错误提示保持不变。

## 测试

测试先覆盖以下行为，再实现代码：

1. 环境开关只接受精确的 `true`。
2. 公开模式下，看板页面不触发登录重定向。
3. 公开模式下，只读汇总 API 不返回 `401` 或 `403`。
4. 开关关闭时，页面与 API 保持现有管理员鉴权。
5. 评测页面、看板 Agent 和写入接口不受该开关影响。
6. 完整测试、静态检查和生产构建通过。

## 部署与验收

代码部署到现有 Vercel 项目 `hookovo`，生产环境设置 `PUBLIC_DASHBOARD_ENABLED=true`。验收标准：

- 未登录访问 `https://hookovo.icu/admin/dashboard` 返回并展示看板，不再重定向到登录页。
- 切换数据来源、筛选条件和刷新功能正常。
- 未登录访问 `/evaluation` 或 `/admin/dashboard/agent` 仍被要求登录。
- 看板写入接口行为与部署前一致。
