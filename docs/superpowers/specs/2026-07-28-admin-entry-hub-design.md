# 管理中心入口设计

## 背景与目标

生产环境已经提供数据看板、策略治理、运营分析 Agent 和评测工作台，但没有 `/admin` 页面。用户直接访问该地址时会收到 Next.js 404，且缺少一个集中发现管理能力的入口。

本次改动新增受保护的 `/admin` 管理中心。它只负责身份校验和页面导航，不复制各子系统的数据、状态或业务逻辑。

## 访问与权限

- 页面使用现有管理员会话与 `classifyAdminAccess()` 判定权限。
- 未登录用户跳转到 `/evaluation/login?next=%2Fadmin`。
- 已登录但不是管理员的用户返回现有禁止访问响应。
- 生产数据库不可用时展示现有 `DatabaseUnavailablePanel`。
- `/admin` 不受公开数据看板开关影响，始终要求管理员身份。

## 页面结构

页面复用现有 `AppHeader`、颜色变量、按钮和面板样式，提供四张主入口卡：

1. 数据看板：跳转 `/admin/dashboard`，查看生成健康度与反馈。
2. 策略治理：跳转 `/admin/dashboard/strategies`，审核、评测、激活和归档策略卡。
3. 运营 Agent：跳转 `/admin/dashboard/agent`，进行只读证据分析。
4. 评测工作台：跳转 `/evaluation`，执行 Prompt 与策略盲评。

策略卡和运营 Agent 的服务端功能开关关闭时，对应卡片显示“当前未启用”，并且不渲染可点击链接。数据看板和评测工作台始终显示。

## 错误处理与边界

- 管理中心不调用策略、运营或评测 API，因此某个子系统故障不会导致入口页整体失败。
- 页面不展示数据库内容、运营指标、策略正文或用户数据。
- 页面不新增 API、权限角色、Cookie 或客户端持久化。
- 原有子页面继续独立执行管理员鉴权，管理中心链接不能替代后端权限校验。

## 测试与验收

- 契约测试首先证明 `app/admin/page.tsx` 缺失，并验证页面必须复用管理员鉴权、登录回跳和四个入口。
- 测试验证关闭功能开关时不会输出受保护入口链接。
- 运行完整单元测试、Agent 评测、文档检查、ESLint、TypeScript、生产构建和安全扫描。
- 部署后验证 `/admin` 未登录返回登录重定向，登录后的管理员可以打开四个已启用入口。
