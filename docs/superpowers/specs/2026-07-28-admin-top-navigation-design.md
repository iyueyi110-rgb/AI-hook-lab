# 管理工作台顶部导航设计

## 背景与目标

当前 `/admin` 是四张入口卡片组成的管理中心，进入具体工具后仍使用只包含“创作台”的通用页头。管理员需要先经过一层入口页，进入工具后又缺少稳定的横向切换和返回层级。

本次改造将管理入口提升到页面顶部，并把数据看板设为管理工作台首页：

- `/admin` 直接展示数据看板；
- 顶部提供数据看板、策略治理、运营 Agent、评测工作台四个入口；
- 子页面提供清晰的“返回数据看板”按钮；
- 数据看板提供“返回创作台”按钮；
- 保留既有权限、功能开关、数据来源和执行逻辑。

## 设计选择

采用独立的 `AdminWorkspaceHeader`，不把管理员权限和功能开关逻辑混入创作台的 `AppHeader`。

该组件负责：

- 展示 AI Hook Lab 品牌和返回创作台入口；
- 展示管理工具导航；
- 根据当前路径高亮当前入口；
- 根据服务端传入的功能开关隐藏未启用工具；
- 在窄屏下允许导航横向滚动，保持单行和可点击性。

管理页面继续在服务端完成身份与功能开关校验。页头只负责显示，不承担授权决策。

## 路由与层级

| 路径 | 页面职责 | 顶部当前项 | 返回按钮 |
|---|---|---|---|
| `/admin` | 数据看板首页 | 数据看板 | 返回创作台 `/` |
| `/admin/dashboard` | 旧地址兼容 | 无 | 服务端重定向到 `/admin` |
| `/admin/dashboard/strategies` | 策略治理 | 策略治理 | 返回数据看板 `/admin` |
| `/admin/dashboard/agent` | 运营 Agent | 运营 Agent | 返回数据看板 `/admin` |
| `/evaluation` | 评测工作台 | 评测工作台 | 管理员返回 `/admin`；非管理员不显示管理导航 |
| `/evaluation/runs/:id` | 评测批次详情 | 评测工作台 | 先返回评测工作台 `/evaluation` |

历史链接 `/admin/dashboard` 保留，但只执行永久兼容跳转，不再形成第二个数据看板地址。登录成功后的管理默认返回地址统一为 `/admin`。

## 顶部导航

管理导航固定包含以下逻辑入口：

1. 数据看板：`/admin`
2. 策略治理：`/admin/dashboard/strategies`
3. 运营 Agent：`/admin/dashboard/agent`
4. 评测工作台：`/evaluation`

策略治理和运营 Agent 受现有服务端开关控制。开关关闭时不渲染入口，避免把管理员带到 `404` 页面。数据看板和评测工作台始终显示。

当前入口使用现有强调红色和底部短线标识，同时设置 `aria-current="page"`。导航项使用已有图标库，不新增图片资源、手绘图标或独立视觉体系。

桌面端导航与品牌位于同一顶部区域。移动端保持品牌和返回创作台入口可见，管理入口在下一行或同一区域内横向滚动，不压缩为难以点击的小按钮。

## 页面返回行为

返回按钮表达信息层级，不依赖浏览器历史：

- 数据看板显示“返回创作台”，固定前往 `/`；
- 策略治理、运营 Agent 和评测工作台显示“返回数据看板”，固定前往 `/admin`；
- 评测批次详情保留“返回评测概览”，固定前往 `/evaluation`。

这样即使用户从书签或外部链接直接进入子页面，返回行为仍稳定可预测。

## 数据看板首页迁移

原 `/admin/dashboard/page.tsx` 的服务端逻辑迁移到 `/admin/page.tsx`：

- 生产持久化不可用时继续显示 `DatabaseUnavailablePanel`；
- 公开只读看板开关继续生效；
- 非公开模式继续要求管理员身份；
- 数据摘要仍由 `getDashboardSummary()` 获取；
- 运营 Agent 功能开关继续传入看板客户端。

原管理中心卡片页和对应 `adminHub` 配置不再参与运行。若没有其他调用方，删除 `lib/adminHub.ts` 及其旧契约测试，避免形成两套入口定义。

## 评测工作台适配

`/evaluation` 同时服务管理员、评测员和裁决员，因此管理导航只能对管理员显示。

服务端页面根据当前用户角色和功能开关构造导航配置，并传给评测客户端：

- 管理员看到完整的管理顶部导航和“返回数据看板”；
- 非管理员保留现有评测工作台页头，不出现无权访问的管理入口；
- 退出登录、账号管理和评测业务逻辑不改变。

评测批次详情不新增跨层返回按钮，继续先返回评测概览，避免绕过正在进行的评测上下文。

## 视觉方向

延续现有瑞士编辑式界面：

- 中性浅灰背景、纯白内容面板、红色单一强调色；
- 无新增渐变、纹理或装饰性图片；
- 1 像素分隔线维持顶部导航结构；
- 当前项红色下划线是主要识别动作；
- 所有文字使用真实产品名称和标准操作文案。

本次视觉差异点是“连续的管理工具轨道”：管理员进入任一工具后，顶部始终保持同一组入口和当前状态，不再回到卡片入口页。

## 权限与错误处理

- 页头不是权限边界；每个页面与 API 继续独立校验身份和角色。
- 功能开关关闭时，服务端页面仍执行 `notFound()`，顶部入口同时隐藏。
- 未登录访问 `/admin` 时跳转到 `/evaluation/login?next=%2Fadmin`。
- 非管理员访问受保护管理页面时继续进入现有禁止访问界面。
- PostgreSQL 不可用时继续显示现有降级面板，不渲染可能误导用户的管理内容。

## 测试与验收

### 自动化契约

- 管理导航入口顺序固定，功能开关正确隐藏治理工具；
- `/admin` 包含原数据看板的数据读取与权限逻辑；
- `/admin/dashboard` 重定向到 `/admin`；
- 策略治理和运营 Agent 使用共享管理页头并返回 `/admin`；
- 管理员评测工作台显示管理导航，非管理员不显示；
- 当前路径正确设置 `aria-current`；
- 不再渲染原四卡管理中心。

### 回归门禁

- 全量单元与契约测试；
- Agent 离线评测；
- ESLint；
- TypeScript；
- Next.js 生产构建；
- 文档语言检查；
- 跟踪文件安全扫描。

### 浏览器验收

- 桌面端检查四个顶部入口、当前项高亮和返回按钮；
- 窄屏检查横向导航不换成拥挤多行；
- 未登录访问 `/admin` 正确跳转；
- 管理员可以从数据看板依次进入三个子工具并返回；
- 旧 `/admin/dashboard` 不出现重复页面或循环跳转。

## 不在本次范围

- 不修改管理 API、策略状态机、Agent 状态机或评测数据结构；
- 不改变经典生成与创作 Agent 页面；
- 不新增角色、权限或登录方式；
- 不重新设计数据看板指标卡；
- 不改变生产功能开关默认值。
